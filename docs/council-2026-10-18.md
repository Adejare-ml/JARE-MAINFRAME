# Jare Mainframe: council review of the whole system (18 Oct 2026)

Five reviewers read the system in parallel, each from one angle, and two
verifiers then tried to knock every finding down against the live database
and the code. Angles: the ingestion pipeline (prompt, 032 to 041, reconcile),
the live data itself (aggregates only, no payee names or balances copied
out), operations and security (workflows, grants, repository settings),
the app surface after the Palette merges, and what is missing outright.
The automated synthesis step ran out of session budget, so this document
was written by hand from the verified findings. Everything below either
reproduced on the live project today or reads directly from the code; the
one claim that did not reproduce is marked refuted.

Context: migrations 038 to 043 were applied live today, #146 (meals from a
photo, 042) and #147 (accounts discovered in mail, 043) were merged, eleven
other PRs were merged or closed and the 17 Oct audit is in
docs/audit-2026-10-17.md. The two edge functions (analyze-meal,
ask-question) are still not deployed.

## The one number that matters

OPay has 51 bank-alert rows since 22 Sep and every one of them is a debit.
GTBank has 46 debits and 7 credits. The reconcile job's "41 missed OPay
alerts and 10 missed GTBank alerts" are not a mailbox mystery: replaying the
balance chain shows the breaks are almost all positive, by thousands of
naira, which is money coming in between two debits. The audit is not
reading credit alerts. Roughly ₦450k of inbound money in 30 days never
reached the ledger, so income, safe-to-spend, save goals, refund matching,
net worth and the month card all run on spending without what came in.

Cause: docs/routine-prompt.md says "Record EVERY alert" in step 2 and "Skip
credits except to note income landing" in step 5, and names only debit
mail templates for OPay. Fix (prompt only, no code): name the credit mail
for each sender next to the debit template, delete the step 5 exception,
and have the task report how many credit mails it found per sender.

## High

1. **Credits never recorded** (above). Prompt fix; then a one-off catch-up
   run over the last 30 days, since `ingest_alert_transaction` answers
   "duplicate" for anything already there and 038 only flags, never
   refuses, old dates.
2. **The audit cannot catch up.** It searches yesterday only. The last
   claude-audit row is 15 Oct 08:11 UTC; 16, 17 and 18 Oct were never
   searched and will not be unless someone re-runs by hand. 95 of 105 alert
   rows were inserted exactly one day after their alert date, so the
   window is one day in practice. Fix in the prompt: read the last ok
   claude-audit run first and search from that date minus one day, capped
   at 14 days, or always search the last three days (duplicates cost
   nothing).
3. **Every alarm ends nowhere.** push_subscriptions has 0 rows, so every
   morning digest for a week ended with "no device subscribed", and the
   first reconcile run (51 gaps) and the three-day audit outage were
   visible only inside the app. Owner: subscribe one phone under
   Settings → Reminders. Code: when any expected job is FAILING or STALE
   and there is no subscriber, remind.mjs should set a non-zero exit so
   remind.yml opens or reopens the sync-failure issue (that path exists),
   or post the digest as a comment on a pinned issue, which GitHub emails.
4. **The digest is printed to public logs.** The repository is public and
   remind.mjs logs the digest title, body and every item line (bill names
   and naira amounts) before it checks for a subscriber. Owner: make the
   repository private. Code: log counts only unless DRY_RUN is set.
5. **The gap list is consumed by nobody.** reconcile_balances names the
   wallet and days of every missed alert; nothing reads that back. Fix: in
   the prompt's step 4, read the latest reconcile summary and re-search
   each named sender on each named day within 14 days, then ingest.

## Medium

- **A run's ok is self-reported.** record_sync_run stores whatever ok the
  model passes and stamps integrations.last_checked; the 11 Oct run
  recorded "0 recorded, 0 skipped: no alerts found" as ok and reconcile
  later found gaps on 9 and 11 Oct. Fix: summary carries "F mails found, S
  statements run"; record_sync_run marks a claude-audit row with 0
  recorded on a mailbox whose 14-day median is above 1 as not ok with a
  note to check the Gmail connector.
- **Reconcile is red for 30 days by design.** 040 records ok=false for any
  gap in the 30-day window, health.js turns any ok=false into FAILING, so
  Settings, Daily HQ and the digest show a permanent red that trains the
  owner to ignore the only alarm for the audit itself stopping. Fix:
  ok=true when the function ran; carry disagreement in the summary with a
  fixed prefix that health.js renders as a third, amber state. Also split
  drift (red) from historical gaps (amber) in SystemHealth and render the
  summary in full, not truncated to one line.
- **The manual-entry match ignores the payee.** 039 links an alert to any
  hand-logged row of the same wallet, direction and amount within ±1 day,
  so a ₦1,000 airtime QuickLog swallows Monday's ₦1,000 POS alert. Fix:
  require payee agreement when both sides have one, prefer same day, and
  only let one alert match one manual row.
- **71 rows wait in review, all LOW,** oldest 2 Aug; 30 are own-account
  transfer refusals, 7 would be caught by the four rules seeded today. 038's
  one-time bulk re-file was skipped during today's apply (blocked by the
  session's safety filter) and is still worth running once from the SQL
  editor. Also: the queue shows a count, never an age; add "oldest N days"
  to the digest line and a bulk "accept the audit's category" for rows
  whose only flag is confidence.
- **The one open loan has three matching repayments and ₦0 paid.** 039
  links on arrival only and there is no way in the app to attach an
  existing ledger row to a debt. Fix: a "Counts toward <debt>" picker in
  the expanded ledger row editor, and a "link past rows" action on the
  Debts card that runs the same match as ingest. A one-off UPDATE on the
  three rows fixes today's number.
- **Silent wallets are invisible.** Health knows whether the audit ran,
  not whether each bank was heard from. Stanbic has had no alert ever;
  PalmPay, Zenith and PiggyVest were created today. Fix: "last alert N
  days ago / never" under each sender in Settings, and a Needs Attention
  line for an active wallet with a sender that has gone quiet. 040 should
  also list the wallets it skipped as unverifiable (no stated balance).
- **Settings rewrites a wallet's balance on every edit** from a form value
  loaded once, so an edit sheet opened before the audit and saved after it
  puts the old balance back, which reconcile then reports as drift. Fix:
  send balance only when it changed, and route deliberate changes through
  log_manual_transaction as an adjustment row.
- **ci.yml has no permissions block** and runs on every pushed branch,
  including Palette and Dependabot branches. Fix: `permissions: contents:
  read` at the top; push trigger on main only, pull_request for the rest.
- **Dependabot will reopen the vite 8 and eslint 10 bumps** weekly and
  merged branches are never deleted (delete_branch_on_merge is off). Order
  for the majors when wanted: @vitejs/plugin-react 6 first, then vite 8
  (check manualChunks still emits the chunks sw.test.js expects), eslint 10
  only after eslint-plugin-react and jsx-a11y allow it. Until then add
  `ignore` entries for semver-major on those three in dependabot.yml and
  turn on automatic head-branch deletion.
- **Export and backup miss four live tables:** meals, monthly_budgets,
  passthrough_transfers, push_subscriptions. buildBundle reports only
  tables whose read failed, so an absent name is silent. Add the first
  three to EXPORT_TABLES and decide push_subscriptions explicitly.
- **Transactions search unmounts itself.** Every debounced keystroke, chip
  or sort change flips `loading` and swaps the page for the skeleton, so
  the search box loses focus and the phone keyboard closes. Keep the
  skeleton for the first load only.

## Low

- Three browser-called functions (correct_transaction,
  log_manual_transaction, log_wallet_transfer) still carry PUBLIC execute,
  so anon can call them; RLS stops any write. One migration: revoke from
  public and anon. (042 and 043 follow the convention.)
- Both edge functions parse the body before checking who is calling;
  ask-question selects `*` from transactions and so drags every raw_email
  through the function for a query that uses six columns. Move auth above
  body parsing; select explicit columns.
- The reconcile chain skips recorded alerts that stated no balance, so a
  correctly ingested no-balance row is reported as a missed one. Carry the
  signed sum of intervening rows between two stated balances.
- remind runs 4 to 10 hours after its 08:20 UTC cron and verify-repo 2 to
  5 hours late; the 6-hour push TTL makes a late digest expire. Moot while
  nobody is subscribed; schedule earlier or move the build into Postgres.
- Goals are all from July and August; seven open goals are past their
  date and October has none. Daily HQ should treat a goal more than 14
  days past its date as one to close or roll.
- The active Transactions chip is read from the URL once and never written
  back, so refresh reverts to the deep-linked filter.
- useRealtimeRefresh can re-use a channel that is still leaving on a fast
  back-navigation and then never re-joins; a unique topic per mount fixes
  it.
- The merged Palette tab roles announce a tabs widget without arrow-key
  handling or roving tabindex; Daily HQ wraps the whole page in one
  tabpanel. One shared hook, or role="group" with aria-pressed as the
  Direction control already does. Colour swatches, the wallet sheet close
  button, the Active toggle and the filter chips are still unnamed or
  carry no pressed state.
- LOW is the prompt's default confidence, so about two rows a day join the
  queue with a real category and no flag. Define HIGH operationally per
  sender (direction and amount are always certain from these templates).

Refuted: "the reconcile summary is cut at 500 characters mid-list". The
live row is 421 characters and complete. The cap in record_sync_run is
real and will bite once more wallets have gaps, so cap each wallet's day
list in the function instead.

## On the discovery feature (043, merged today)

The council judged the design while the branch was still open and most of
it matched. Three points to sharpen in a follow-up:

- Do not auto-note from the ingest refusal path. A task typo such as
  `gt-bank` mints a junk account and a junk question. Keep sightings to the
  explicit note_discovered_account call and have the refusal name the
  nearest known slug instead. (043 as merged does auto-note; a probe row
  from today's live verification was left as `probe043`, status ignored,
  and can be deleted.)
- Add `asked_at` and `snooze_until` so "ask again next week" is a column,
  not a date computed from first_seen_at.
- When the slug already belongs to a wallet, let note_discovered_account
  update that wallet's stated balance ("balance noted") rather than
  returning noted=false, and backfill 14 days of that sender after Track.
