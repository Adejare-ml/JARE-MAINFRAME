# Jare Mainframe: audit and improvement plan (10 Oct 2026)

Sources: three read-only code reviews (app surface; pipeline, scripts and
migrations; tests, quality and security) plus the live database and Actions
history for 28 Sep to 10 Oct. Every item below was checked in code or data.

## What the live system says

- Every job ran. The pg_cron snapshot fired 12 times at 10:00 UTC exactly.
  The backup fails as designed (no repository or token yet), issue #120.
- The review queue grew from 24 to 68 rows in twelve days. No category rule
  exists. The design assumes a daily review that is not happening, so the
  queue, not the pipeline, is now the bottleneck.
- Own-account moves are still being re-filed as spending: GTBank prints the
  name truncated ("ADEJARE OLUWAGBEMILEKE", 4 rows), and GTBank card top-ups
  into OPay ("WEB PUR OPAY CHARGE", 6 rows, ₦23,800) carry no payee at all.
- OKash repayments of ₦45,000 sit in the ledger while the OKash debt shows
  ₦0 paid and 25 days overdue. Nothing links a repayment to a debt.
- The 1 Oct month plan did nothing ("no active monthly coding goal") and
  recorded a clean success. October has no goals at all.
- Palette merged another PR (#113) on its own.

## Tier 1: fix now (one PR each, about a week of sessions)

### 1. Make ingestion categorise without you
- Own-name match: accept a truncated recipient that is a prefix of an own
  name, and match on word boundaries (036 matches "ADE" inside "SHADE").
- Seed rules from the data: `description contains OPAY CHARGE → Transfer
  Out`, `recipient contains OKash → Loan Repayment`; order rules by
  specificity (`priority, length desc, created_at desc`) so an old broad
  rule never beats a newer specific one; a rule should not bypass the
  own-name check unless its value names an own account.
- Payee memory: when the owner has filed a payee the same way twice, the
  next alert from that payee gets that category at HIGH. Suggest a rule in
  the queue after the third time.
- Re-file by direction (`type`), refuse payees under 4 characters.
- Bulk "Apply" must not default to Uncategorized or record a correction to it.
- Needs Attention "Review →" opens `/transactions?filter=Review`.
Files: 038 migration (ingest function, `jare_names_own_account`, rule order,
seed rules), categoryRules.js, Transactions.jsx, DailyHQ.jsx. Effort M.

### 2. Money-math defects
- "Save at least" goals count every credit (salary, refunds, Transfer In) as
  saved; Daily HQ's safe-to-spend rises on payday. Count only savings or
  investment wallets. planning.js:151.
- "Spend under" goals ignore the liquid-wallet rule Budget uses. planning.js:154.
- Goals page drops this week's weekly goals in the first days of a month. Goals.jsx:93.
- Reminder digest and Upcoming Bills list salary and own-account transfers
  as bills. reminders.js:67, recurring.js:84.
- A misread date in the past is inserted at HIGH and counted in an old
  month; add a `stale_date` flag below today minus 10 days. 036:217.
- Two untimed alerts on one day: only the first moves the balance. Compare
  on (date, time, created_at). 036:224.
Effort M total.

### 3. Manual entries and alerts double-count
A QuickLog entry followed by its bank alert inserts a second row and can
move the balance twice (the "already imported" check skips MAN- rows on
purpose). Link a matching MAN- row (same wallet, amount, type, ±1 day)
instead of inserting, skip the derived balance move, and show a badge.
This also closes the known debts "Log payment" double-count. Effort M.

### 4. Debts that pay themselves down
Link repayments to a debt by counterparty (a rule-like `debt_match` on the
debt, applied in the ingest function and on review), hide payouts whose
date passed and loans whose linked payments cover the principal, roll a
monthly due date forward. Effort M.

### 5. Scripts: one owner, whole data, honest runs
- `resolveOwnerUserId` never reads `jare_owner`; a stray sign-up stops every
  Actions job. Read the pin first.
- weekly-recap, verify-repo, plan-month and backup read every account's rows
  with the service key; add `user_id` filters.
- weekly-recap reads up to 60 days in one request (silent 1000-row cap); page it.
- plan-month: run days 1–7, skip once drafts exist, record "no goal yet"
  as a real summary and surface "set an October goal" on Daily HQ.
- remind: latest row per job with no 35-day window; NEVER counts as unwell
  for expected jobs; zero devices after having some is not ok.
- backup: add `id` as a second sort key, export `categories`,
  `jare_owner.own_names` and the integrations row minus the token.
- snapshot: mark not-ok when the last audit is older than 30 h; prune
  `cron.job_run_details` after 30 days.
- Failure-issue steps search only the 10 newest issues; search by title.
Effort M total.

### 6. Security before anything else is deployed
- `ask-question` serves any signed-in account with the owner's paid key:
  owner check against `jare_owner`, 500-character cap, CORS to the Pages
  domain, Lagos month boundary. Do this before it is ever deployed.
- Security headers in `public/_headers` (CSP, nosniff, referrer policy,
  frame-ancestors). The session token lives in localStorage.
- Owner: turn off sign-ups in Supabase Auth; make the repository private.
Effort S.

## Tier 3: new features (pick two or three)
1. Nightly reconciliation: for each wallet compare the last stated balance
   with the previous one plus the transactions between; a gap over ₦1 is a
   failing "reconcile" job in the morning alarm. Catches missed alerts.
2. Anomaly alerts in the digest: unusually large debit for a payee, first
   payment to a new payee over a threshold, wallet too low for a bill due.
3. More banks: PalmPay, Zenith, PiggyVest alerts are in the mailbox
   (declined on 28 Sep). Store each wallet's sender address so the task's
   Gmail query comes from the database.
4. Refund matching: pair a credit with an earlier debit from the same payee
   and net it, instead of counting it as income.
5. Passthrough flag: money that passes through you for someone else, left
   out of spending and income. The live table already has the columns;
   nothing in the code uses them.
6. Split a transaction across categories.
7. Month-end recap on the 1st: spend vs budget per category, net-worth
   change from snapshots, top payees; compare to a 4-week average.
8. Confirm a detected bill into a tracked one with a due-date alert.
9. Debt payoff planner (snowball / avalanche, projected dates).
10. Finish the light theme with semantic tokens (about 670 hardcoded
    white/black utilities). Large.
